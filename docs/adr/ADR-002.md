# ADR-002: 金额一律用"分"存储(BIGINT)

- **状态**: 已接受
- **日期**: 2026-09-15

## 背景

订单金额、退款金额等字段若用 DECIMAL/FLOAT,存在浮点误差风险(DW 计算累计误差)、跨库兼容问题与换算口径混乱。

## 决策

- 数仓全部金额列用 **BIGINT,单位为分**。API 若返回元(字符串/浮点),在 ODS 装载前统一换算:解析为 Decimal → 乘 100 → 取整,转换失败进死信表(etl_load_error)。
- 展示层(BI)由 Superset 计算字段 ÷100 还原为元。

## 后果

- 优点:无浮点误差;聚合 SUM 安全;跨库跨语言一致。
- 代价:BI 与 SQL 人工查询时需注意单位,数据字典中所有金额字段必须标注"单位:分"(见 docs/data-dictionary.md)。
