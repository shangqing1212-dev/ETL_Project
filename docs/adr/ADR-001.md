# ADR-001: 时间统一按 Asia/Shanghai 本地时间存储

- **状态**: 已接受
- **日期**: 2026-09-15

## 背景

电商业务在中国大陆单区域运营。若按 UTC 存储,自然日统计(日 GMV、日报)会在 08:00 产生日界偏移,导致 DWS 聚合与业务口径不一致。

## 决策

- 数仓中所有日期时间列(stat_date、updated_at、etl_loaded_at 等)一律存 **Asia/Shanghai 本地时间**(无时区标记的 DATETIME)。
- 应用层(Python)统一用 `zoneinfo.ZoneInfo("Asia/Shanghai")` 计算窗口。
- MySQL 容器/实例 `default-time-zone='+08:00'`,连接串 `time_zone='+08:00'` 显式设置,消除 JDBC/驱动差异。
- `stat_date` 与自然日对齐,业务口径一致。

## 后果

- 优点:日界与业务一致;DWS/ADS 聚合简单直白;运维排查直观。
- 代价:若未来出海多区域,需引入 UTC 基准 + 多时区维度,本次改造为有意的技术债,已在此记录。
